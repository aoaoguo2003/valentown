## 这是什么

七个居民住在同一座小镇：按各自的作息醒来，走去咖啡馆和药房，写信，
互相借钱，约时间地点，当面把东西交到对方手里。

有意思的地方不是「LLM 在驱动他们」，而是**世界可以拒绝**——而且这个世界的
每一处设计，都被量过值多少钱。

Agent 挑一件工具，世界拿自己的规则去核：店关门了、你要找的人不在这儿、
你还差五块。然后给出理由。Agent 带着这个理由重新规划。这个循环一直转，
直到它做出一个**占用游戏时间**的动作。

```
状态 → LLM → 调用工具 → 世界 → 观察 → LLM → … → 动作
                    └── 可以拒绝，并给出理由 ──┘
```

### 改造前后

小镇原本是另一个样子：每轮一次 LLM 调用，模型被摁着填一张固定的表
（`action` / `destination` / `duration` / `talk_to`），而世界永远说 yes。
那个版本作为 `pre-rebuild` 消融**留在评估里**——这样「改造带来了什么」
是和它本身比出来的，不是和对它的描述比出来的。

| 任务 | 现在 | 改造前 |
|---|---|---|
| **errand 跑腿** — 读信 → 接任务 → 借钱 → 买 → 约见面 → 当面交付 | **7/7**，中位 74 次决策 | **0/2**，卡在 6 环的第 1 环，约 215 次决策 |
| **rendezvous 碰头** — 蛋糕只能当面交 | **6/7**，中位 28 次决策 | **0/2**，走到 4 环的第 0–1 环，约 215 次决策 |
| **scarcity 抢购** — 一盒药两个买主，不许超卖 | **7/7**，中位 40 次决策 | **0/2**，3 环的第 1 环，约 248 次决策 |

改造前的设计一道题都做不成，而且**要花三到六倍的决策去失败**。它只会走路。

<sub>136 格评估 · 6.6 小时 · 5900 万 tokens · 0 个废格 · 0 次重试。
基线和 `pre-rebuild` 来自同一批、同一个 commit。rendezvous 那唯一一次失败
已定位到一个世界 bug，已修——见 [诚实的局限](#诚实的局限)。</sub>

## 一个会说「不」的世界

拒绝不是错误处理，它就是内容本身：**一个从没被拒绝过的 agent，不需要做规划。**

| 规则 | 它让 agent 付出什么 |
|---|---|
| **只看得见同一区域的人** | 想知道谁在哪？只能写信问。世界知道，但没有任何一个居民知道。 |
| **店有营业时间，每家三个位子** | 药房 9–18 点。去晚了门就是关的。 |
| **下雨天户外锚点被拒** | 真实伦敦天气，按游戏小时取。户外是**按锚点**判的，不是按区域——露台关了，同一家店的室内还开着。 |
| **开局 15 块，每三天再领 15** | 一杯咖啡 8 块。开口借钱不是点缀，是唯一的出路。 |
| **交东西必须两个人都在场** | 钱可以隔空转账，东西不行。 |
| **两个买主，一盒药** | 扣货和扣钱在同一把锁里完成，所以「先查再买」不可能超卖。**31 次并发抢购，0 次超卖**，而且赢家不总是同一个人。 |

拒绝理由**绝不泄露 agent 不该知道的事**：

```
✅  "Emma Harris is not at Café_bar."
❌  "Emma Harris is at Park."          ← 等于白送一张全镇位置表
```

**拒绝理由指向哪里，比它出现多少次更要紧。** 围绕同一堵墙做了四个实验——
agent 站在药房里，差 5 块钱：

| 做法 | 说话的时机 | 结果 |
|---|---|---|
| 把价格放进上下文 | 买之前 | 0/3 |
| 在工具描述里叮嘱「先对一下钱包」 | 买之前 | 0/3 |
| 加一个必填 `cost` 字段，逼它把数字打出来 | 买之前 | 0/3 |
| **在拒绝理由里点明那条出路** | **撞墙那一刻** | **0/14 → 3/3** |

三次失败的共同点是**都在事前做文章**。看它当时的想法就明白了——
*"Adam has a fever and needs cold medicine."* **任务一急，约束就隐形。**
有效的那段措辞给的是**岔路口**不是答案，并且点明了一件模型无从推断的
世界规则：**这镇上没人能当面把现金递给你。**

## 怎么证明这些设计真的有用

基线自己考得好说明不了什么——可能只是题简单。所以**每次只摘掉一个能力，
再跑同一道题**。

|  | errand | rendezvous | scarcity |
|---|---|---|---|
| 基线 | ✓ 7/7 | ✓ 6/7 | ✓ 7/7 |
| 发不出信 | **✗ 0/2** — 卡在「凑够药钱」 | ✓ 2/2 | ✓ 2/2 |
| 没有跨轮记事本 | **✗ 0/2** | ✓ 2/2 | **✗ 0/2** |
| 不能约时间地点 | ✓ 2/2 | ✗ 1/2 | ✓ 2/2 |
| 每轮只准想一步 | **✗ 0/2** | ✗ 1/2 | **✗ 0/2** |
| 改造前 | **✗ 0/2** | **✗ 0/2** | **✗ 0/2** |

**失败是交叉的。** 摘掉发信，跑腿死了、碰头没事；摘掉约见面，反过来。
**没有任何一样东西是「关了就全线崩」**——这才说明这套消融在测能力，
而不是在测题目有多脆。

<sub>有一行不干净：摘掉约见面会连带让「递交提醒」失效（它挂在「手上有任务」
这个条件上），所以它那一列不能单独归因给约见面这件工具。**一条消融必须只关
一样东西**，这条关了一样半——写在这里，而不是当作干净结果拿去用。</sub>

最锋利的一条结论来自多步循环。`single-step` 给模型全部十四件工具，
但每轮只准想一步。它在跑腿和抢购上全败，在碰头上赢了一次：

> 跑腿这条链要求 agent **在同一轮之内改主意**——查货架、发现差五块、
> 当场改成写信借钱。碰头不需要：走过去是一轮，递出去是下一轮。

所以多步循环**不是**普遍的智能升级。**它只买到一样东西：不花游戏时间就能
重新规划的能力**——而且只在任务真的需要它的时候才显形。

三道题共 10,212 轮的实测：**1,640 次拒绝，而被拒之后 agent 换招的比例是
100%**（各格中位数）。世界会反驳，而 agent 听得进去。

## 工程

**慢 I/O 永远不进临界区。** LLM 调用（最长 60 秒）和天气请求都在锁外完成；
一次决策只持锁两次、各几微秒——取世界快照一次，提交一次。

```
七人各走一步       0.25s     单次调用 0.20s —— 几乎完全重叠
七人各走两步       0.42s     两次调用 0.40s
同样的活，把调用放回锁里   1.43s   ← 改造前的形态
```

第三行是**故意留着的反证**：将来谁把慢调用挪回锁里，前两个测试就不再测真东西，
而这一个会立刻变红。（而且**不用 asyncio**——线程在 I/O 上已经完美重叠，
**能说清「为什么不用」比用了更值钱**。）

**提交前重跑一次 handler。** 模型思考的那几十秒里世界会变，最后一个座位
可能已经被抢走。所以决策落地之前，要拿一份新鲜快照再核一遍。

**给不会自愈的故障装一道闸。** 401/402/403 是账户级的。撞上第一次就拉闸，
之后每次调用立刻返回。没有它的时候，余额见底之后系统又打了 **1,927 次**
注定失败的请求，产出三十格垃圾数据——而记分卡上它们看起来就是「模型很差」。
同样的故障注入下，现在只发出 **1 次**。

**一张会承认自己不知道的记分卡。** 模型一次都没成功应答过的格子标 `ERR`，
**整个不进对照表**；被决策预算掐断的标 `✗⏱` 而不是 `✗`。多环任务报告走到了
第几环——因为「药买到了但没送出去」和「一整天什么都没干」不是同一种失败。

**追踪，以及从追踪里反算的指标。** 每次 LLM 调用、每步工具调用都当场追加一条
JSONL；指标层是独立的**读**的那一侧，零项目依赖，所以任何一份日志都能离线、
免费地重算行为和成本。

## 记忆、检索、反思

- **每人一份滚动记忆**，保留 15 个生活日。
- **重要性由 LLM 打分** —— 每条记忆按触动程度打 1–10 分，而不是一个常数。
- **三因子检索** —— `时近 × 重要 × 相关`，相关度用本地 embedding 算余弦相似度
  （fastembed / bge-small，不需要 API key，离线可跑）。
- **每晚反思 → 演化中的自我描述 → 第二天的提示词**，让反思真的够得着行为。
- 检索是**一件 agent 自己调的工具**（`recall`），不是每次都往提示词里塞的
  top-12 大块头。

## 诚实的局限

**模型默认别人在他该在的地方。** `target_absent` 是最常见的拒绝理由——整轮评估
撞了 **907 次**。它选择走过去看看，而不是写信问。单步用例三次全错。

**买之前不检查买不买得起。** 上面那四个实验在**撞墙那一刻**解决了它，
这救得了多步场景，救不了单步的第一个选择——那个用例至今 0/3。

**有一处改动留在代码里，但它还没挣到自己的位置。** 当居民就站在他欠东西的
那个人面前时，有三行字会提醒他。单步用例在那个处境上从 **0/4 变成 9/9**。
但**端到端的消融没能复现**：基线 4/4，摘掉那三行是 3/4，n=4。这道题一天只
产生一两次「该递」的时刻，二元判据太钝——要分辨 90% 和 65%，每边大约需要
三十格。**这是测量精度的问题，不是反对它的证据**——所以它写在这里，
不写在亮点里。

**有一个 bug 混进了一次真跑。** 重复提议一个已经存在的约定，会把双方的
那条记录一起删掉——回滚是按「这两个人 + 地点 + 时刻」模式匹配的，
而不是按「这次调用刚创建了什么」。136 格里只踩中一格，而那一格正好就是
上面 rendezvous 唯一那次失败，**在记分卡上它和「模型放弃了」长得一模一样**。
已修，规则的两半各有一条测试钉着。

## 快速开始

```bash
cd backend
python -m venv .venv
# Windows: .\.venv\Scripts\Activate.ps1   |   macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # 填 LLM_API_KEY —— DeepSeek 的 key 开箱可用
python main.py              # http://localhost:5000
```

```bash
cd frontend
npm install
npm start                   # http://localhost:8080
```

首次运行会下载一个约 100 MB 的本地 embedding 模型用于记忆相关度。
**没有 API key 小镇照样跑**，走确定性兜底决策；LLM 加的是「决策、说话、反思」。

```ini
LLM_API_KEY=your_key
LLM_BASE_URL=https://api.deepseek.com   # 任何 OpenAI 兼容端点
LLM_MODEL=deepseek-v4-flash
```

## 结构

依赖方向**严格单向**，从下往上。

```
world/       小镇由什么构成 —— 时钟、地点、经济、天气、信箱、任务、事件，
             以及**唯一**一处装配世界快照的地方
   ↑
tools/       agent 能对它做什么 —— 14 件工具，每件 = schema + handler
   ↑
runtime/     决策循环、调度器、上下文组装。**不认识任何一件具体工具**
   ↑
api/ main.py HTTP 契约与薄启动器

agents/  memory/  observability/  evals/  llm/     横跨在旁边，被上面几层使用
```

| 包 | 里面是什么 |
|---|---|
| `world/` | 数据与原子操作。`economy.py` **故意**把货和钱放在一起：买一次东西要同时改五样，**原子性边界决定模块边界**。 |
| `tools/` | 工具注册表。每件工具自己声明：占不占游戏时间、每轮最多几次、谁有资格用。循环只数次数，它不需要知道「信」是什么。 |
| `runtime/` | `agent_runtime.py`（循环）、`scheduler.py`（一座隔离的小镇，离线试跑和评估共用）、`context_builder.py`（这一轮让居民看见什么）。 |
| `evals/` | 场景、消融、runner、记分卡。**判据只看世界状态。** |
| `observability/` | `trace.py` 在热路径上写；`metrics.py` 读日志反算，零项目依赖。 |

## 命令

```bash
node scripts/smoke_24h.js         # 作息 + 路径冒烟测试，在仓库根跑
```

```bash
cd backend
pip install -r requirements-dev.txt
python -m pytest tests/ -q                              # 483 个测试，无 LLM、无真实网络
python -m observability.metrics logs/<某份日志>.jsonl     # 行为 + 成本，离线，免费

python ../scripts/dry_run.py --days 2 --scenario errand # 真实驱动整座小镇（花钱）
python -m evals.tool_choice --repeats 3                 # 8 条单步用例，约两分钟
python -m evals.runner --scenario all --ablate all --repeats 2 --note 全矩阵
```

每次跑都会拿到一个带编号的目录（`logs/eval_v18_备注/`），里面一份 `run.json`
记着命令、commit，以及**工作区脏不脏**——**一个说不出自己跑的是哪份代码的
版本号，只是个流水号**。

## 范围

一个研究原型：单个 Flask 进程、JSON 存档、七个居民。**前端才是生产环境的
调度器**——后端回答「下一步做什么」，浏览器把它播出来。为本地实验而造，
不是为规模。

> 灵感来自 *Generative Agents: Interactive Simulacra of Human Behavior*
> (Park et al., 2023)；设计与实现从零写起。
